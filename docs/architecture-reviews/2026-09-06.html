问题
三条 Evidence-Bearing Query Attempt 入口各自拼 reject / classify / persist。Pair 在仓库里是 deep 的；execute 这个 module 仍泄漏两套 persist 栈，Template Execution 靠 setter 挂上。

做法
加深 Execution Evidence Pair：即时 execute、Template Execution、Related Record Navigation 只提交终端结局和可审计身份。

  • locality：取消与 pair 失败的缺陷集中到一个 module
  • leverage：一条 persist 路径，三个调用方
  • interface 变窄；implementation 吸收 reject / persistAttempt / persistNavigationAttempt
  • 测试打一条 interface，不再复制三套矩阵

Health Observation 不进这个 module

问题
Inventory Mutation 散成三个写入 module 加一个持久化堆。完整性（名称唯一、关系方向、Environment 局部性）和审计从 seam 泄漏出去；healthStatus 被当成 Manual Health Override 来 PATCH。

做法
一个 Inventory Mutation module 拥有 CI 身份、Typed Profile、CI Relationship，以及同一事务里的字段前后审计。Health Observation 不走这条路径。

  • locality：完整性规则不再住在三个调用方里
  • leverage：Manual CI Registration 和日后的 CI Ingestion 共用一次写入
  • interface 就是这次 mutation；测试断言审计 pair，而不是 SQL 形状
  • 删掉两份 Typed Profile 字段图
当前写入与 2026-08-29-inventory-mutations-and-audit-commit-together、inventory-integrity-is-server-owned 冲突。加深是落实这两份决策，不是重开。同时对齐 health-observations-are-not-inventory-mutations。

问题
Related Record Navigation 在 execute module 里重写了整条治理链，跳过 Query Guard，拿裸 DSN 打 inspector。理解一个概念要同时读 Execute 和另一条约 180 行的路径。

做法
Related Record Navigation 成为拥有受信任 FK SELECT 构造的 module。它经 Execution Evidence Pair 落证。它不是第二个公开 SQL 执行器。

  • locality：FK 信任与导航证据身份放在一起
  • leverage：pair module 被复用；executeGuardedChain 留给受 Guard 的 SQL
  • 删掉 rejectNavigation / persistNavigationAttempt 副本
受 2026-07-14-phase-38j 约束：独立路由，不并进 POST /execute，不做通用绑定 SQL 执行器。加深发生在 execute 旁边，不是并进去。

问题
Operator Access Boundary 被重述成 RouterAdmin、HandlerAdmin，以及查询 module 里的 isAdmin。披露 403 不发 auth.authorization/denied。requireAuthenticatedActor 与 requireFreshQueryActor 是同一段实现。

做法
一个 module 拥有矩阵、未认证与禁止两种结局，以及 denied 审计。HTTP 只把结果挂到请求上。

  • locality：每一次角色拒绝都是同一种结局
  • leverage：测试打矩阵，而不是每个 handler 副本
  • interface 变窄；RouterAdmin / HandlerAdmin 收拢
2026-08-15 已把两套中间件工厂列为后续。真正的摩擦是矩阵分裂，不是工厂拷贝。Console BFF 按 2026-08-09 是另一套 adapter —— 不要把 Operator Session cookie 拉进这个后端。

问题
Schema Inspection 的 HTTP module 是五份 shallow 的 access/cache/audit 拷贝。Related Record Navigation 和 Query Disclosure 拿裸 DSN 打 inspector，最热的路径上 Schema Metadata Identity 并不生效。

做法
Schema Inspection 是现场对象与 FK 元数据的唯一权威。导航和披露穿过这条 seam；不再开第二条 inspector hop。

  • locality：FK 元数据只有一条受治理路径
  • leverage：缓存和 schema 审计也覆盖导航
  • interface 从五个长相一样的方法收成「检视这个身份」

加深 Topology Traversal

值得展开 in-process

加深后 · 深的边界

Interface · 体积受限的图，超出则 truncated

Database Estate 分类
代理角色来自 Typed Profile

问题
Topology Traversal 用深度上限挡住一条本可返回的 Database Estate 路径。分类是 deep 的；边界却是 interface。代理主备从 CI Labels 泄漏。

做法
Interface 是带 truncated 标记的体积受限图。展开策略和 Database Estate 含义留在 implementation，读 Typed Profile 而不是 Labels。

  • locality：截断与分类集中在一个 module
  • leverage：调用方只学「图或 truncated」，不学跳数算术
  • 测试断言输出体积，而不是 depth 1 对 2
当前深度上限与 2026-08-29-topology-is-bounded-by-output-size 冲突。加深是落实该决策。
